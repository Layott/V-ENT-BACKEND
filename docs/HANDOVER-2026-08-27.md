## The rates

Seeded by hand in migration 0052 and stale the day they were written. The seeded
cedi rate was `0.0098` when the real one is `0.008273`: a 15 per cent error on
every price a Ghanaian reader was shown, and nothing on the platform said so,
because a stale rate looks exactly like a good one.

They now come from `https://open.er-api.com/v6/latest/NGN`. No key, no account,
daily, base NGN, and it carries all 14 currencies with none missing. This was
checked against the live feed before anything was built on it. Nothing about
V-ENT is sent to it: it is a GET for a table of public numbers.

**The feed is allowed to fail.** A refresh that cannot reach it leaves every
existing rate exactly as it was and reports why. Rates are display-only, since
money moves in naira through Paystack and a VENT COIN is a naira amount, so a
stale rate makes a guide slightly wrong while a blank one would make prices
unreadable. Never trade the second for the first.

Guards, all covered by tests in `vent_auth/tests_rates.py`:

- a rate outside `0.0000001` to `100000` is refused rather than written
- the naira is never written from the feed, and cannot be moved off 1 or
  switched off by hand
- a currency missing from the feed is skipped, never zeroed

**The cron is live on the VPS:**

```
0 4 * * * cd /srv/vent/backend && ./venv/bin/python manage.py refresh_rates >> /srv/vent/logs/rates.log 2>&1
```

Ran by hand on production the same day: `Updated 13 rates.` The command exits 0
on a feed failure, so a dead feed does not page anybody at 4am. Check
`/srv/vent/logs/rates.log` if a rate looks old.

`/auth/admin/rates/` is restricted to `super_admin` and `finance_admin`. Moving a
rate changes what every reader sees a price as, which is structural rather than
moderation.

## The dates

67 formatters were pinned to a language that was not the reader's:

| count | what it said |
|---|---|
| 39 | `'en-GB'` |
| 18 | `'en-US'` or `'en-NG'` |
| 10 | `undefined` |

That last group is the one worth remembering. `toLocaleString(undefined, …)`
looks like "no opinion" and quietly means **the browser's language**, not the
site's. Grepping for quoted locale strings misses every one of them, which is
why the first sweep looked finished and the French event page still printed
`Sep 16, 2026, 12:30 AM`. It was only caught by opening the page.

They now read `src/lib/appLocale.js`, published by `LanguageProvider` on every
render. Notes on the shape:

- **A hook would not work.** About a third of the sites are plain helpers
  (`walletHelpers`, formatters defined above a component) where a hook cannot be
  called.
- **Set during render, not in an effect.** A date formatted on that very render
  would otherwise print in the language the page was last in.
- **It lives apart from `src/lib/locale.js` on purpose.** That file is imported
  by the middleware, which runs per request, and a module-level value shared
  between requests there would be somebody else's language. The first attempt
  overwrote `locale.js` outright and broke every page with
  `'splitLocale' is not exported`.

The two server routes that build metadata keep `'en-NG'`. Their date sits inside
an English sentence and translating half of it would read worse than not.

Verified live in three languages on the same record: `16 sept. 2026, 00:30` /
`16 de set. de 2026, 00:30` / `Sep 16, 2026, 12:30 AM`.

## Open, and not done

- **The date range inputs on `/tournaments` still show `mm/dd/yyyy`.** That is
  the native control drawing itself from the browser's own language, which a
  page cannot set. Replacing it means replacing the control.
- **Currency names on `/admin/rates` are English**, because they come from the
  `Currency` table. Admin-only, so left alone.
- **`~/.ssh/vent-vps.txt` still holds the VPS root password and a live Resend
  API key in cleartext.** Flagged before; still true.

## Traps worth knowing before touching this

- **`pnpm build` overwrites `.next` under a running `pnpm dev`.** The dev server
  then serves 404 for every dev CSS chunk and the page renders unstyled. It
  looks like a CSS bug and is not. Kill dev, `rm -rf .next`, restart.
- **`node_modules/next` empties periodically on this machine.** The symptom is
  `Cannot find module 'next/dist/pages/_app'`. The fix is deleting
  `node_modules` and `pnpm install --force` from PowerShell.
- **A synthetic `blur` event does not reach a React `onBlur`.** React listens for
  `focusout`. A hand-set rate looked broken in testing for this reason alone,
  and the real mouse path worked the whole time.
- **The Chrome `computer` tool takes screenshot coordinates, scaled up to CSS by
  the ratio between them.** Here that is 1745/1425. Clicking at coordinates read
  off a screenshot lands somewhere else entirely, which reads exactly like a dead
  button. Get the element's `getBoundingClientRect()` and multiply by 0.8166.
