## The pattern, stated once

**The failure mode of this codebase is silence.** Not one of the faults below
raised an error, failed a build, failed a lint, or failed a test. Every one was
valid code doing something wrong quietly, and every one was found by looking at
the running product rather than by reading the diff.

Corollaries worth carrying:

- **An element that returns null looks exactly like an element that is switched
  off.** Seven of the eight studio graphics are off at any moment, so a broken
  one is invisible until somebody turns it on with real data.
- **A 200 with a well-formed URL to a page that does not exist is still a bug.**
  Nothing in the stack can tell you the URL points nowhere.
- **A helper that returns null by contract is only half a contract.** 63 render
  sites passed that null straight to `<img>`.
- **Two surfaces for one job means one of them is forgotten.** Drafts, overlays,
  short links, tickets. Every time.

## Bugs by class, with the cause

### Vocabulary: two halves of one feature naming things differently

**The overlay prompt invented field names.** It listed `tournament_name`,
`home_score`, `event_name`. The feed sends `tournament.title` and a `teams`
array, and `static/overlay-runtime.js` resolves a dotted path against those
roots. Every name in that prompt resolved to an empty string, so a designer
following it precisely would have produced an overlay that filled with blanks on
air. Three more of the same kind, all silent: the event feed sent flat top-level
keys (a bare name resolves against `scope`, null outside a repeat); it had no
`version`, so poll two saw `undefined === undefined` and the overlay would have
frozen at its first frame for the whole broadcast; and it read `session.room`
where the field is `stage`.

**The studio player card** matched on `p.username`; the feed sends `ign`. It
found nobody and drew nothing, for every operator since it was written.

**The bracket graphic** read `R2  0 - 0` and named nobody: the feed's live rows
carried the round and the score and no participants.

Catchers: `tests_overlay_vocabulary.py` mirrors the runtime's resolution rule and
asserts every promised name resolves against a real feed, both kinds.
`tests_overlay_templates.py` asserts every name in every shipped element is one
that vocabulary allows. Chain: template → vocabulary → feed.

### Address: the two ends disagreeing about what an id is

**Every studio URL was a 404.** `request.build_absolute_uri` builds against the
host that made the request, which is always the API because it is the frontend
calling. So Copy URL produced `https://api.v-ent.co/studio/<token>/scorebar/`,
and the element pages are frontend routes. API 404, frontend 200. The one thing
the feature exists to produce did not work, for anybody, ever. The element pages
now come from `FRONTEND_URL`; the feed keeps `build_absolute_uri`, because the
feed **is** an API route. Two bases, not one.

**"Pending BE deploy" on an endpoint that shipped months ago.** The console
addresses a tournament by slug; **26 routes** took `<int:tournament_id>`, which
does not match a slug. Django answered 404 and the frontend read any 404 as "not
deployed yet". Measured: by slug 404, by id 409. Every one of cancel, generate
bracket, distribute prizes, check-in, stages, requirements, rules, standings and
league rules was unreachable from the console offering it. All converted to
`<str:>` resolving through `vent_tournament/lookup.py`.

### Missing middle: both ends built, nothing joining them

**Following an organisation showed an empty feed, for everybody.** The follow
worked and the feed was written correctly. 0 of 10 tournaments and 0 of 5 events
carried an organisation, because nothing anywhere could set one. Both columns had
existed from the beginning. `vent_auth/org_link.py` is the resolver both creates
and both edits share; `GET /organization/mine/` fills the picker.

**Tickets and capacity in the event wizard.** `create_event` had accepted
`ticket_types` and `capacity` all along; the wizard sent neither.

### Absent control: the thing simply was not there

Ten buttons with no `onClick`. Sponsor upload with a ref never attached. No way
to delete a draft on the page that lists drafts. Join live to a signed-out
visitor. A register wizard handed to somebody with no account.

### Presentation: the record is right and the screen is wrong

A club with no artwork drew two broken images across its hero. A cancelled
tournament belonged to no status bucket and vanished from My Tournaments
entirely. The help bubble sat on top of Buy ticket at 390px, measured with
`elementsFromPoint`. A filled avatar sat in the corner of its box.

### Language: sentences written for an engineer, shown to a person

"Pending BE deploy - this action activates once the backend endpoint ships."
"Authorization header with a Bearer token is required." Twenty-six sites did
`setError(err.message)`, and the API's message is written for the log and only
ever in English. Three `window.confirm`/`alert` dialogs drawn by the browser with
none of the product on them. All fixed; `apiMessage` itself no longer passes
machine text through.

## The checkers

Twenty-two scripts under `V-ENT-FRONTEND/scripts/`, plus the Python ones under
`tools/`. State at close:

| Clean | Standing count, not yet zero |
|---|---|
| check-control-bytes, check-dangling-refs, check-error-ui, check-inert-controls, check-keys, check-null-images, check-signed-out, check-status-buckets, check-tdz, dict-parity | check-avatars **23**, check-css-classes **201**, check-design **399**, check-seo **61**, check-slugs **21** |

`check-embeds` needs the dev server on 127.0.0.1:3000 and reports nothing without
it, which is worth knowing before trusting its silence.

### Four carry a self-test, and every checker should

`check-signed-out`, `check-null-images`, `check-error-ui`, `check-status-buckets`
run fixtures of the real shapes against the live matcher on every invocation.

**This is the single most important lesson of the day.** A checker reporting zero
has two meanings and nothing distinguishes them. Measured events:

- `check-signed-out` went to a passing **zero three separate times** while the bug
  was still in the tree: a greedy parameter match swallowed the handler body; then
  bounding the body at the next declaration ended it at the `const res =` on the
  handler's own first line; then testing only the first `&&` in a chain read
  `openMenu === m.id` and called a guarded block unguarded.
- `check-null-images` accepted a guard that merely **contained** the expression, so
  `{club.bannerUrl && <img src={mediaUrl(club.banner)} />}` read as guarded.
- `check-error-ui` matched a hand-written list of six setter names, so
  `setFeedback(err.message)` sailed through — and widening it found **nine more
  real sites** in files already reported clean.

Every one of those was found by deliberately attacking a gate that had passed.

### Calibration is half the work

`check-null-images` first reported **63**. Fifty-four were already correct,
guarded by the raw field rather than by `mediaUrl(field)` — just as safe, because
the helper only returns null for a falsy input. A checker that reports correct
code is one people stop reading, which is worse than not having one. The false
cases are fixtures too.

`check-inert-controls` reported 50 and settled at 10 the same way: buttons wrapped
in a `<Link>` work, and ten of the seventeen files were components no page imports
any more. Both checkers now resolve the import graph from the page roots.

## Mistakes I made, recorded as mistakes

1. **Committed to `main` twice** on the frontend before branching. Caught both
   before pushing; moved each commit to a branch with `git branch`, then
   `git branch -f main origin/main` while standing on the new branch. No
   `reset --hard`, nothing lost, nothing reached the remote outside a PR.
2. **Built the tickets step into dead code.** `src/components/create-event-component/`
   is imported by no page; the live wizard is `src/app/events/create-event/page.js`
   and already had those steps. I checked the tournament wizard, saw the parallel
   event component beside it, and assumed symmetry instead of asking which one the
   route renders. The dead tree is deleted, eleven files.
3. **`data.get(...)` in a function that only has `request.data`.** Would have
   broken every tournament creation. `create_tournament` swallows exceptions into
   a generic error, so it presented as "the tournament was not created" rather than
   a traceback. The suite caught it.
4. **Reported "63 images that can render as broken".** The real number was nine.
5. **Created a `BroadcastSession` on production by hand** to walk the studio
   elements, pointed at `lagos-codm-clash`. Deleted afterwards;
   `BroadcastSession.objects.count()` is 0.
6. **Wrote invisible control bytes twice** by putting `\b` and `\n` through a
   Python heredoc. `check-control-bytes` caught both. Use the Write/Edit tools for
   anything with escapes.
