## The bugs, and why none of them could be seen

Every one of these was invisible to the build, the linter and the tests. That
is the pattern worth carrying forward: **the failure mode of this codebase is
silence**, not errors.

**The overlay vocabulary.** The event overlay work merged first thing listed
field names like `tournament_name`, `home_score`, `event_name`. Nothing sends
those. The feed sends `tournament.title` and a `teams` array, and
`static/overlay-runtime.js` resolves a dotted path against those roots. Every
name in that prompt would have resolved to an empty string, so a designer
following it precisely would have produced an overlay that filled with blanks
in front of an audience.

Three more of the same kind, all silent, all found by reading rather than by a
test failing:

- the event feed sent flat top-level keys; the runtime resolves a bare name
  against `scope`, which is null outside a repeat, so every one read as empty
- the event feed had no `version`; the runtime redraws only when that moves, so
  poll two would have seen `undefined === undefined` and the overlay would have
  frozen at its first frame for the whole broadcast
- it read `session.room`; the field is `stage`

**Player card.** Matched on `p.username` and `p.name`. The feed sends `ign`,
`id`, `img`. It found nobody and returned null, for every operator since it was
written. An element that returns null looks exactly like an element that is
switched off, which is the normal state of seven of the eight at any moment.

**Bracket.** Read `R2  0 - 0` and named nobody, because the feed's live rows
carried the round, the score and no participants.

**Join, signed out.** On organisations it answered `Authorization header with a
Bearer token is required` after the press. On teams it did nothing at all.
`/tournaments/<slug>/register` handed a signed-out visitor the whole wizard and
refused them at the end.

**Follow Organizer.** A `<button>` with no `onClick`. Not a broken handler: no
handler. Full width under the organiser's name on every tournament page, inert
for everybody since it was written.

## The catchers, and the one that matters

Three new ones, and a lesson about the third.

`scripts/check-inert-controls.mjs` reports any `<button>` with no onClick, no
submit, not disabled, not Link-wrapped and not a form's own submit. It found 50;
two calibration passes took that to the ten a person can genuinely press.

`vent_tournament/tests_overlay_vocabulary.py` mirrors what the runtime does with
a name and asserts every name the prompt promises resolves against a real feed,
for both kinds. `tests_overlay_templates.py` asserts every name in every shipped
element is one that vocabulary allows. The chain is template -> vocabulary ->
feed, all three asserted, none able to drift alone.

`scripts/check-signed-out.mjs` gained fault 3, and **this is the important
part**: it went to a passing zero three separate times while the bug was still
in the code.

1. a greedy parameter match ran past the end of the line and swallowed the
   handler body, so `const handleApply = async orgId => {` was never seen as
   authenticated while `const save = async () => {` was
2. bounding the body at the next declaration ended it at the `const res =` on
   the handler's own first line
3. testing only the first `&&` in a chain read `openMenu === m.id` and called a
   guarded block unguarded

So it now carries a **self-test**: three real shapes, run against the live
matcher on every invocation, that fail loudly if the checker stops seeing a
fault it was built for. Without it, `0` means either "clean" or "broken" and
there is no way to tell which. Every checker in this repo should have one.

## What the signed-in walks found

All four ran once the CEO signed in on the emulator, and every one of them
turned up something. That is the argument for walking rather than reading.

**B5, following an organisation.** The follow worked and the feed was EMPTY, for
everybody: 0 of 10 tournaments and 0 of 5 events carried an organisation,
because nothing anywhere could set one. The columns had existed from the
beginning. There was also a booby trap in the only place the link was read,
`t.tournament_organization.name` where the field is `org_name`, which would have
raised AttributeError the first time the feature worked.

**C5, clubs.** Every club drew TWO BROKEN IMAGES across its hero on the day it
was made. `mediaUrl` returns null by contract so the caller can draw a fallback;
the page passed the null to `<img>`. 63 more render sites do the same, listed by
`scripts/check-null-images.mjs`, with `img:not([src]){display:none}` as the floor
under all of them until each gets a real fallback.

**12, the studio console.** Copy URL put `https://api.v-ent.co/studio/<token>/
scorebar/` on the clipboard. That is the API host; the pages are frontend
routes. API 404, frontend 200. EVERY URL the studio had ever produced was
unusable, and nothing could report it: a 200 with a well-formed URL to a page
that does not exist.

**4, rules in the wizard.** The walk corrected me. I had built a Tickets step
into `create-event-component/`, which is dead code no page imports, and reported
the gate on it. The live wizard already had those steps. `capacity_mode` and the
organisation genuinely were missing and are now there; the dead tree is deleted.
