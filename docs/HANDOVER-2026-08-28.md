## The auth change is the one to know about

The console no longer has a sign-in of its own. An admin proves the second
factor at the **ordinary** sign-in, and the console reads that session.

This did not weaken anything. Before, an admin could use the whole site with a
password alone and only met a code if they went looking for the dashboard. Now
every admin sign-in takes the code.

What makes a session an admin session is one field, `login_session_2fa_at`, set
only by the code path and cleared by anything else. Two places check it:
`resolve_admin`, and `may_override` in `actors.py` - and **`may_override` had no
such check at all**, so a password-only admin session could overrule an owner
through ordinary endpoints. A test caught it. If a third place ever needs to ask
"is this an admin acting", it asks the same field.

`AdminTOTP` is retired in favour of `UserTOTP`; migration 0054 folded confirmed
console secrets across so no existing admin re-enrols. The old rows are kept.

## Three hangs, one shape

Three separate admin screens sat on "Loading..." for ever today, and all three
were the same fault: a `fetch` that rejects, inside an async function that sets
a loading flag and never clears it because the rejection unwinds past the
`finally` that would have.

  * `/admin/games` - reported by the CEO
  * `/admin/rates` - the same helper
  * `/admin/partners` - a dead backend session behind a live NextAuth one

**If a page can spin for ever, it will.** Every one of these now reports the
failure and offers a way out. When writing a new admin page, the fetch helper
gets a `catch` that returns a shaped error, not a bare `await fetch`.

## The wizard was losing work

"Logo and banner did not save" was two faults:

1. The preview lived in the wizard step's own state, so moving to another step
   unmounted it and coming back showed empty boxes. The file was still held and
   would still have been submitted, but nobody believes that.
2. The file was also read into a base64 data URL and written into the draft,
   which goes to localStorage. A 5MB image is ~6.8MB of base64, over the 5MB an
   origin gets, so `setItem` threw - and the `catch` around it swallowed the
   error, **losing the whole draft**.

Nothing about an image goes into localStorage now. If you add another upload to
a wizard, hold the `File` in the parent and preview from an object URL.

**Still broken, logged as M5:** sponsor logos have never saved on either wizard.
The submit sends names, types and usernames only.
