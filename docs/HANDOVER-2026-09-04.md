# Handover, 4 September 2026

Four asks from the CEO in one session, and one of them was about why an earlier
ask had been reported done when it was not.

---

## 1. "there is a lot more formations than these"

`vent_cards/formations.py` went from 8 to **28** formations: every shape EA
ships, with its real name including the lettered variants that are genuinely
different shapes rather than the same one renamed.

`vent_cards/tests_formations.py` (18 tests) pins the count and the properties
that make a formation usable. Two of them are worth knowing about:

- **The first number of the name must equal the defenders in the back band.**
  This caught `3-5-2 (2)`, which carries LWB and RWB: in that shape they are two
  of the five in midfield, and their depth on the pitch says so. Counting by
  position alone called it a back five.
- **No two slots closer than about an eighth of the pitch in BOTH directions.**
  A card has a size. The goalkeeper's card sat on top of the middle centre back
  in every back three and back five, with distinct coordinates and green tests,
  visible only in a browser.

## 2. "i hjave not seen the UI of where the players submit and how they pick"

Because it was not there. Inbox rows 28, 29 and 30 were marked done with a
backend and no screen: submitting, the organiser's decision and the squad rules
all had endpoints with nowhere to press them.

Built:

| File | What it is |
|---|---|
| `LineupPicker.js` | Submit squad, separate from Save draft, with the rules and the violations above the pitch and why a disabled Submit is disabled |
| `SquadStatus.js` | Shared by both sides: the rules, the spend, the state, the organiser's reason. Every line built from a CODE the server sent plus its numbers |
| `SquadReviewPanel.js` | The organiser's rules editor and the queue, with Accept and Send back. A rejection will not send without a reason |

Nothing in the browser works out whether a squad is legal. `POST /lineup/` now
returns `violations`, `spend` and `squad_rules` alongside the lineup, so the
screen that just saved knows where it stands from the same engine the submit
endpoint uses.

## 3. "the cards dont carry the full design"

`FutCard` drew a rating, a position and a name over whatever Futbin's CDN
returned, and hid the stats at the size the pitch uses. And
`cdn.futbin.com/design/img/cards/tiny/<type>.png` **answers 404**, so every
seeded card fell back to a plain coloured band.

The card is drawn from the data now: rating, position, nation, portrait, name,
club and all six stats, with no network at all. Futbin's art is a layer on top
when it loads. A goalkeeper shows DIV HAN KIC REF SPE POS. One layout at every
size: `--fut-w` sets the width, the font size comes from it, everything inside
is `em`, and the pitch and bench set that variable.

## 4. "Are the player cards on the website the actual cards from futbin?"

**No, and no scraping has ever been done.** Full answer in
`tools/README-futbin.md`. In short:

- The catalogue holds 25 hand-written demo rows.
- The portraits were built from EA player ids that I had guessed. Rendered side
  by side: "Victor Osimhen" showed Phil Foden, "Wilfred Ndidi" and "Samuel
  Chukwueze" showed white players, Bruno Onyemaechi answered 404. The demo now
  ships **no portraits at all**, because a face under the wrong name is worse
  than initials.
- The stats were `80/80/80/80/60/75` on all 25. They are each player's own
  shape now.
- **The scraper is configured on this machine as of today.** Playwright and
  Chromium installed, `scrape-futbin.mjs` reaches Futbin, and it stops at the
  Cloudflare gate. **A person answers that once**; the profile keeps the
  clearance afterwards. That is where the first real run stopped.
- `CARDS_INGEST_KEY` is not set on either side yet. The server answers 503
  `INGEST_NOT_CONFIGURED` until it is.

## The one that matters most: "why is it still happening?"

> "i thought a check was built for frontend so that any backend design that
> needs a frontend ui, gets the ui built. we hvae seen this eror like 3 times
> now. why is it still happening?"

Three separate reasons, all fixed.

**The check was too loose.** `endpoint-callers.py` joined every frontend file
into one blob and asked whether each word of a route appeared in it. On a
codebase this size almost every word appears somewhere, so
`tournament/<id>/lineup/submit/` was reported as CALLED because `lineup` is in
the picker and `submit` is in the KYC page. Two unrelated files.

The unit is now a FILE: the route's last literal segment must be used as a path
in one file, and every other segment must appear in that same file. One line
was measured and abandoned on 3 September (helpers hold half a path); the whole
frontend is too loose; a file is neither.

**Nothing ran it.** `check-all.py` is the one command that gets run and this
checker was not in it. **Neither were 20 others** that had been written and
were sitting on disk. All are in it now: 30 catchers, blocking where they are
at zero and reported as debt where they are not.

**There were two copies of it.** One at the workspace root and one in the
backend repo, drifted by a day and a half, with the documentation naming both.
The root is not a git repository. The backend copy is the only copy now, the
root files are six-line forwarders so every documented command still works, and
`check-duplicate-checkers.py` fails if a real second copy appears again.

Both new checkers carry a `--self-test`, 9 and 4 fixtures, each a real shape
including the fault that shipped.

### What the honest checker then found

**22 endpoints with no screen able to reach them**, now in the baseline and

self check-in settings, adding a vendor, a vendor's orders, marking an order
collected, head to head, league rules, the whole stage system, rule presets,
team ownership transfer and role assignment, and saved payment cards.
